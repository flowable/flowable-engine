# Unit 5: Engine Common & Process Engine Schema DDL Scripts - Change Summary

## Overview
Authored Cloud Spanner (GoogleSQL dialect) schema DDL scripts for Flowable Common (`flowable-engine-common`), Process Engine Core (`flowable-engine`), and BPMN History (`flowable-engine`), providing create and drop scripts that strictly comply with Cloud Spanner GoogleSQL constraints and Flowable's modular schema management architecture.

In Round 2 (Rework), fixed GoogleSQL DDL syntax and dependency teardowns surfaced by real Cloud Spanner Emulator validation:
- Removed unsupported `IF EXISTS` from `ALTER TABLE <table> DROP CONSTRAINT` statements.
- Added explicit teardown for all foreign keys and all secondary and unique indexes prior to table drops in `drop.common.sql`, `drop.engine.sql`, and `drop.history.sql` (Cloud Spanner rejects dropping tables with active indexes or referencing foreign keys).
- Fixed index name typos (`_IDX_`) and added unique index drops in `drop.engine.sql`.
- Removed extraneous `RETRIES_` column from `ACT_RU_DEADLETTER_JOB` in `create.common.sql`.
- Enhanced unit tests (`SpannerCommonDdlTest` and `SpannerProcessEngineDdlTest`) to rigorously assert syntax rules, index teardown symmetry, and absence of unsupported clauses.

## Decisions & Defaults
- **Table Partitioning / Layout**: Followed developer-confirmed policy [`SPN-D4`](file:///usr/local/google/home/vaibhavch/sam-teamfood/flowable-engine/.sam/plan.md#L46) using flat standalone tables with secondary indexes rather than interleaved composite keys, maintaining uniform `ID_ STRING(64)` primary keys across Flowable entities.
- **Identity Key Generation**: Applied native GoogleSQL `BIT_REVERSED_POSITIVE` identity generators (`GSQL-C1`) for auto-incrementing serial columns (`ACT_EVT_LOG.LOG_NR_` and `ACT_HI_TSK_LOG.ID_`) to avoid monotonically increasing sequential hotspotting without requiring separate sequences.
- **Nullable Uniqueness Constraint**: Used `CREATE UNIQUE NULL_FILTERED INDEX` (`GSQL-C5`) instead of standard unique constraints on nullable composite columns (`ACT_RE_PROCDEF`, `ACT_PROCDEF_INFO`, `ACT_HI_PROCINST`) to prevent treating multiple null keys as constraint collisions.
- **Index and Foreign Key Teardown Order**: Cloud Spanner strictly prohibits dropping a table if secondary indexes exist on it or if active foreign key constraints reference it. Teardown scripts are sequenced: Foreign Keys -> Indexes -> Tables.
- **GoogleSQL Drop Constraint Syntax**: Cloud Spanner does not support `ALTER TABLE ... DROP CONSTRAINT IF EXISTS`. All constraint drops use standard `ALTER TABLE <table_name> DROP CONSTRAINT <constraint_name>;`.
